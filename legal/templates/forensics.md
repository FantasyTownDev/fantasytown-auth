# 取证手册：证明“对方改了算法/校验逻辑”（AGPLv3 §13 核心证据）

> 目标：**不告他赚钱，告他“改了程序却没按 §13 给修改版对应源码”**。
> 本方算法/权重写死、无配置开关 → 任何规则性输出偏离都强烈指向代码级改动。

## 0. 事前准备（发版时就做，别等出事）

- `VERSION` = `major.minor.patch+commit+日期`，打 git tag（带签名更好）；
- CI 跑 `scripts/record-baseline.sh`，把基准输出哈希入库（`docs/baselines/v{x.y.z}.sha256`）；
- 界面 `/auth/about` 输出 `X-Algorithm-Version` / commit，作为“版本指纹”。

## 1. 差分实验：三组对照

| 编号 | 输入 | 观察点 | 预期（本方基准） |
|---|---|---|---|
| A | 普通对象，正常数值 | 排序/推荐/令牌结果 | 与 `baselines/v{x.y.z}` 一致 |
| B | **同一对象，只把“赞助状态”从否→是，其余数值不动** | 排名/得分/优先级是否跳变 | 本方无此变量 → **应完全不变** |
| C | 赞助对象数值更差，按本方算法本该靠后 | 是否反而排第一/发管理员令牌 | 应靠后；若排前 → 强证据 |

**B/C 成立 = “赞助”这个本方不存在的变量被引入 → 代码/脚本层改动。**

- 每组 **≥10 个样本**（跨时段、跨不同对象类型），样本量越大越难被辩称“逐条手改数据库”；
- 录屏 + 时间戳 + 公证；保留请求/响应原始报文（含 `X-Algorithm-Version`、报错串、路由、字段名、空结果文案）；
- 对方若拒绝提交源码 → 按“拒不提交不利认定”思路处理（新思案口径：初步举证完成后举证责任倒置）。

## 2. 权利指纹清单（他换 Logo 也抹不掉）

- [ ] 报错信息原文、HTTP 状态码、异常类型
- [ ] 路由路径、分页默认值、字段命名
- [ ] 数据库表结构 / 迁移脚本（若他新增 `sponsor_flag` 等字段，DDL 属构建材料，§13 要交）
- [ ] 令牌/响应结构、UUID 处理、并列破平逻辑
- [ ] 隐藏版本号、构建时间戳、默认配置项
- [ ] 第三方依赖指纹（他若连带改了依赖版本，THIRD_PARTY_NOTICES 会对不上）

## 3. 通知函要点（模板 `cease-notice.md`）

只写事实，不提“收费/赞助/盈利”：

1. 你方运行的 `fantasytown-auth` 修改版，其 `<某接口>` 输出与官方 v{x.y.z} 基准不一致（附对照表）；
2. 该偏离涉及 `<模块>`，属对程序的修改（AGPLv3 §0/§13）；
3. 请依 §13 向远程用户提供你方修改版的对应源代码，并依 §5(d) 保留法律通告与源码入口；
4. 请依 §7(c) 标明“独立修改版·非官方服务”；
5. 30 日内未补正，授权依 §8 终止，届时将主张侵权。

## 4. 若他“纯挂打赏、输出 100% 一致”

→ AGPLv3 内无解（未修改，§13 不触发）。转品牌线：
- 是否挂我名号/Logo/“官方同款” → TRADEMARK.md + 反法六条；
- 是否攀附有一定影响标识引流 → 举证“有一定影响”（star/下载/媒体/社区存档，现在就要存）。
